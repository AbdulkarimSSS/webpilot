محرك أتمتة واستكشاف وتشغيل متصفحات متقدم وشامل (General-Purpose Autonomous Browser Engine)، مصمم للتعامل مع أي موقع ويب أو تطبيق أحادي الصفحة (SPA) أو بوابات التوظيف والشركات الكبرى مثل (**SAP SuccessFactors**, **Workday**, **Greenhouse**, **Oracle Taleo**) بدون أي محددات مسبقة خاصة بالمواقع (Zero Hardcoded Selectors).

## 🏗️ المعمارية ثلاثية الطبقات (3-Tier Process Architecture)

لحل المعضلة الجوهرية في نظام تشغيل ويندوز حيث تقوم برامج إدارة الأوامر والتيرمينال بإنهاء كافة العمليات الفرعية فور انتهاء الأمر (`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`)، تم ابتكار معمارية WebPilot المستقلة ثلاثية الطبقات التي تعمل **دون أي صلاحيات إدارية (Zero-Elevation)**:

```text
 ┌──────────────────────────────────────────────────────────────┐
 │     واجهة الأوامر والشيل التفاعلي (webpilot / wp / shell)    │
 └──────────────────────────────┬───────────────────────────────┘
                                │ HTTP REST (127.0.0.1:9333)
                                ▼
 ┌──────────────────────────────────────────────────────────────┐
 │        الطبقة الأولى: المشرف العام (Master Supervisor Host)   │
 │   • خفيف للغاية (~15 ميجابايت رام - بدون مكتبات Playwright)  │
 │   • مراقب خمول تلقائي لمدة 30 دقيقة (Watchdog)               │
 │   • تشغيل تلقائي مستقل عبر WMI خارج قيود شجرة التيرمينال     │
 └──────────────────────────────┬───────────────────────────────┘
                                │ قنوات دخل/خرج معزولة (JSON-RPC)
                                ▼
 ┌──────────────────────────────────────────────────────────────┐
 │        الطبقة الثانية: العامل التشغيلي (Operational Worker)   │
 │   • يحمل بيئة Playwright ومنسق الجلسات (Session Coordinator) │
 │   • يحتفظ بجلسة المتصفح والصفحات المفتوحة حية في الذاكرة     │
 │   • خدمات الـ DOM (Field, Auth, Reactive, Inspection)        │
 └──────────────────────────────┬───────────────────────────────┘
                                │ ارتباط مباشر بشجرة العمليات
                                ▼
 ┌──────────────────────────────────────────────────────────────┐
 │        الطبقة الثالثة: محرك المتصفح (Chromium Browser Engine) │
 │   • العملية الرئيسية لـ Chromium ومعالجات الرندر والجرافيك   │
 │   • قتل تعاقبي فوري وشامل مع الطبقة الثانية بدون عمليات زومبي│
 └──────────────────────────────────────────────────────────────┘
```

### ⚡ المزايا المعمارية الكبرى:
1. **استمرار جلسة المتصفح عبر أوامر الـ CLI المنفصلة**: إمكانية تنفيذ أوامر متتالية خطوة بخطوة (`فتح الصفحة` $\leftarrow$ `إدخال البريد` $\leftarrow$ `إدخال كلمة المرور` $\leftarrow$ `الضغط على زر الدخول`) دون إعادة تشغيل المتصفح أو فقدان حالة الـ DOM.
2. **العمل بصلاحيات المستخدم العادي (Standard User Mode)**: تعمل المنظومة بنسبة 100% كمستخدم عادي دون طلب صلاحيات Administrator أو شاشات UAC أو أدوات رفع الصلاحيات (`asudo`).
3. **القتل التعاقبي والتعافي اللحظي (Cascading Kill & Instant Self-Healing)**: إنهاء الطبقة الثانية عبر `taskkill /F /T /PID` يبيد المتصفح وعملياته التابعة فوراً في جزء من الثانية دون أي تسريب لعمليات زومبي (Zero Zombie Leaks)، بينما تظل الطبقة الأولى حية وتقوم بإعادة تشغيل طبقة ثانية نظيفة خلال **~300ms**.
4. **مراقب الخمول الذكي (30-Minute Watchdog)**: تفرغ المنظومة 100% من ذاكرة المتصفح تلقائياً إذا تركت الجلسة خاملة لمدة 30 دقيقة.

## 🌟 الميزات الجوهرية للمشروع

- **استكشاف النماذج الشامل (`inspect`)**: فحص أي رابط واستخراج مخطط JSON خفيف ومحسن للتكلفة والرموز (Token-Optimized Schema) يوضح الحقول، القوائم المنسدلة، أزرار الاختيار، مربعات التحديد، مناطق رفع الملفات، والأزرار التفاعلية.
- **التعبئة الديناميكية للحقول (`apply`)**: تعبئة الحقول عبر ملف JSON خارجي (`--data`) أو عبر وسائط مباشرة (`--fill`) مع التعرف الذكي على نوع الحقل (نص، قائمة، راديو، كومبوبوكس).
- **المراقبة التفاعلية المتقدمة (Reactive Interaction Service)**:
  - مراقبة التغيرات الناتجة عن النقر على الأزرار (`--press`).
  - اكتشاف عمليات إعادة التوجيه وتغير المسارات تلقائياً (`[🔀 Redirect]`) وإعادة فحص الصفحة الناتجة فوراً.
  - اكتشاف النوافذ والتبويبات الجديدة (`[🌐 New Window]`) والتحول إليها تلقائياً.
  - اكتشاف توسع النماذج الديناميكية والقوائم الأكورديونية (`[📋 Dynamic Form Expansion]`).
- **معالجة حواجب التحميل والانتظار (Dynamic Loader Dissolution)**:
  - التعرف التلقائي على شاشات وحواجب التحميل (`#loading`, `.sapUiBusy`, `.busyIndicator`, `.modal-backdrop`, `[aria-busy="true"]`) والانتظار الديناميكي الذكي حتى تلاشيها واختفائها تماماً.
  - التفريق بين حاجب المحتوى العام للشاشة وبين اللودر الموضعي داخل القوائم المنسدلة.
- **سلسلة التفاعل التكيفي وحل النوافذ المنبثقة (Modal & Reactive Interaction Pipeline)**:
  - معالجة النوافذ المنبثقة ومربعات الحوار عبر 4 استراتيجيات تكيفية آمنة: المعرف المباشر (ID) $\leftarrow$ فئات الأدوار والنصوص (ARIA/Text) $\leftarrow$ النقر البرمجي المباشر (JS Fallback) $\leftarrow$ بروتوكول زر `Escape` القياسي، دون أي تعديل جراحي أو تخريب في بنية الـ DOM.
- **خوارزمية التمرير التلقائي للقوائم المعقدة (Picklist Auto-scrolling)**:
  - تمرير واختيار ذكي في القوائم الافتراضية الضخمة (مثل قوائم SAP التي تستخدم `aria-owns` وحاويات تمرير مخصصة).
- **الوضع التفاعلي اللحظي (Interactive REPL Shell)**:
  - شيل تفاعلي سريع للغاية يتيح إدخال الأوامر خطوة بخطوة بالثواني مع إكمال تلقائي ومعاينة فورية.

## 🚀 دليل الاستخدام السريع

يمكنك استخدام الأمر الكامل `webpilot` أو الاختصار السريع **`wp`** (أو `python cli.py`):

### 1. إدارة خدمة المشرف العام (Master Supervisor Service)
```powershell
# فحص حالة الطبقات الثلاث والعمليات النشطة
wp service status

# تشغيل الخدمة بالخلفية تلقائياً
wp service start

# إعادة تشغيل العامل التشغيلي والمتصفح مع تنظيف الذاكرة
wp service restart

# إيقاف الخدمة بالكامل وإغلاق كافة العمليات
wp service stop
```

### 2. فحص محتوى وبنية أي صفحة ويب
```powershell
wp inspect --url "https://example.com/apply" --output "schema.json" --screenshot "page.png"
```

### 3. الأتمتة المتسلسلة على نفس الجلسة المستمرة
تنفيذ أوامر متتابعة خطوة بخطوة على **نفس جلسة المتصفح الحية**:

```powershell
# الخطوة 1: فتح البوابة وفحص عناصر تسجيل الدخول
wp apply --url "https://example.com/login" --screenshot "step1.png"

# الخطوة 2: تعبئة البريد الإلكتروني فقط في الصفحة النشطة
wp apply --fill "username=john.doe@example.com" --screenshot "step2.png"

# الخطوة 3: تعبئة كلمة المرور فقط في الصفحة النشطة
wp apply --fill "password=MySecurePassword123!" --screenshot "step3.png"

# الخطوة 4: الضغط على زر تسجيل الدخول ومتابعة التوجيه وفحص الملف الشخصي وحفظ الكوكيز
wp apply --press "Sign In" --cookies "session_cookies.json" --screenshot "step4.png"
```

### 4. وضع الشيل التفاعلي (Interactive REPL Shell)
لتشغيل شيل تفاعلي سريع والاستجابة في أجزاء من الثانية:
```powershell
wp shell
```

داخل الشيل:
```text
webpilot> open https://example.com/login
webpilot> fill username=john.doe@example.com
webpilot> fill password=MySecurePassword123!
webpilot> press Sign In
webpilot> tabs
webpilot> screenshot dashboard.png
webpilot> exit
```

## 🛠️ دليل أوامر الـ CLI (Command Reference)

### الخيارات العامة
- `--host`: عنوان المشرف العام (الافتراضي: `127.0.0.1`).
- `--port`: منفذ المشرف العام (الافتراضي: `9333`).
- `--standalone`: تجاوز المشرف والتشغيل كعملية بايثون مفردة تقليدية داخلية.

### أمر الفحص `inspect`
- `--url <URL>`: الرابط المراد فحصه (اختياري إذا كانت هناك جلسة حية بالفعل).
- `--output <path>`: مسار حفظ ملف JSON الناتج.
- `--screenshot <path>`: مسار حفظ لقطة الشاشة.
- `--cookies <path>`: ملف الكوكيز لجلسات تسجيل الدخول.
- `--unpack-options`: استكشاف خيارات القوائم المنسدلة بعمق.
- `--tab <index>`: استهداف تبويب محدد عبر رقمه.
- `--list-tabs`: عرض كافة التبويبات المفتوحة في الجلسة.

### أمر التطبيق والتعبئة `apply`
- `--url <URL>`: الرابط المستهدف (اختياري إذا كانت هناك جلسة مفتوحة).
- `--data <path>`: مسار ملف JSON يحتوي على خريطة الحقول وقيمها.
- `--fill <key=val>`: تعيين قيمة لحقل معين (يمكن تكراره عدة مرات).
- `--press <btn>`: الضغط على زر مع مراقبة التغيرات الناتجة (يمكن تكراره).
- `--upload <kw=file>`: رفع ملف في منطقة الرفع المطابقة للكلمة المفتاحية.
- `--cookies <path>`: مسار حفظ أو تحميل ملف الكوكيز.
- `--submit`: الضغط على زر الإرسال النهائي.
- `--screenshot <path>`: التقاط لقطة شاشة بعد انتهاء التفاعل.
- `--no-auto-inspect`: تعطيل الفحص التلقائي للصفحة الناتجة بعد النقر.
